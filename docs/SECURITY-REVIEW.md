# MYMS 디버깅·보안 점검 — 2026-11-24

범위: 현재 로컬 앱 소스, 저장 파일, 인증/서버 통신, BLE 패킷, 카메라 추적 및 포함 런타임. 기존 전신·손 추적/UI 변경을 보존했다. 운영 DB·서버 설정·Arduino 펌웨어는 변경하거나 업로드하지 않았다.

## 수정한 사항

| 항목 | 발견 및 조치 |
| --- | --- |
| 손상된 운동 데이터 | 음수 목표를 저장 파일에서 정상 로드하는 현상을 테스트로 재현했다. 계획·횟수·세트·점수·시각 범위를 검사하며, 잘못된 저장 파일은 덮어쓰지 않고 보존한다. 잘못된 편집도 롤백한다. |
| 인증 요청 대상 | URL 문자열 결합/강제 해제를 제거했다. HTTPS의 지정 Supabase 호스트·포트·API 경로만 허용하고 외부 호스트로의 리다이렉트를 차단한다. |
| 인증 응답 캐시 | 공유 URLSession 대신 디스크 캐시·쿠키 저장을 사용하지 않는 ephemeral 세션을 사용한다. |
| 로그인 토큰 | Keychain WhenUnlockedThisDeviceOnly를 사용한다. 삭제 후 재생성 대신 update-first로 교체하고 OS 오류를 확인한다. 로그아웃 표시와 세션 세대 검사를 추가해 오래된 응답/토큰 복원을 차단한다. |
| 계정별 서버 요청 | 계획·기록 요청에 명시적 user_id 조건을 넣고 INSERT 소유자를 현재 계정으로 고정한다. 저장된 전송 대기열은 계획/기록 API만 호출할 수 있다. 이는 서버 RLS를 대신하지 않는다. |
| 기기 운동 기록 | iOS 저장 파일에 Complete 파일 보호를 적용하고 기존 파일도 접근 시 보호 속성을 갱신한다. |
| 진단·비밀번호 | 카메라 진단 파일은 기본 비활성화, 시작 시 이전 파일 제거. 필요할 때 MYMS_POSE_DIAGNOSTICS=1로 명시적으로 활성화한다. 활성화해도 영상은 저장하지 않고 보호된 진단 값만 기록한다. 화면을 나갈 때 입력 비밀번호 상태를 지운다. |
| BLE 거리 입력 | 보드 펌웨어 규격과 맞게 0~2000mm만 받아들이고 잘못된 길이/범위는 미측정으로 처리한다. |

공개 배포용 Supabase publishable key는 관리자 비밀 키가 아니다. 이를 숨기는 것으로 서버 보안을 대신하지 않았으며 키 회전도 하지 않았다. 참고: https://supabase.com/docs/guides/api/securing-your-api

## 확인한 결과

- 실제 iPad Air 11인치(M2): 인증 요청 주소/캐시 정책, 별도 테스트용 Keychain 토큰 업데이트·접근성·삭제, 로그아웃 복원 차단, 저장 파일 보호, Thunder·MediaPipe 추론 검사를 포함한 XCTest 9개 통과, 실패 0개.
- Mac: 센서 디코딩/범위, 로컬 기록·통계, 체크포인트 복구·중복 완료·일일 상한, 손상 데이터 거부·계정 요청 범위 검사를 실행했다. 원본 보존과 롤백도 검사했다.
- 운영 API 읽기 전용 점검: 인증 토큰 없이 profiles/workout_plans/workout_sessions에 select=id&limit=1 GET을 보냈고 모두 HTTP 401, PostgreSQL 42501(권한 거부)을 반환했다. 실제 사용자 ID/행은 수집·출력하지 않았다.
- 최종 일반 앱 빌드·엄격한 코드 서명/런타임 포함 검증이 통과했고, iPad 설치를 완료했다. 사용자가 잠금을 해제한 뒤 앱 실행에 성공했고, 실행 중인 프로세스도 확인했다.
- 코드 검토에서 중요한 추가 회귀는 발견되지 않았다. 빌드/테스트 성공은 아래 미확인 항목의 안전성을 보장하지 않는다.

## 남아 있는 서버·실기기 확인

1. **인증된 두 계정 간 RLS 격리:** 비로그인 거부만 확인했다. 담당자가 별도 테스트 계정으로 다른 사용자 행 읽기·수정·삭제 및 user_id 변경이 거부되는지 검증해야 한다. 읽기 전용 설정 확인 SQL은 `SECURITY-DB-READONLY.sql`에 있다.
2. **서버 점수 검증:** 저장소 DDL은 points_earned를 클라이언트 INSERT로 받으며 행당 0~300만 검사한다. 서버에서 운동량 기반 계산·일일 합계·동일 세션 중복 완료를 트랜잭션으로 강제하는 RPC/트리거 적용 여부는 확인하지 못했다. 현행 앱만으로 변조 클라이언트의 점수 조작을 막을 수 없다. 서버 담당자와 계산/상한/멱등성 규약을 정한 뒤 서버·앱을 함께 바꿔야 한다.
3. **BLE 인증:** 보드 ID 읽기/대조는 식별이며 암호학적 인증이 아니다. 현행 프로토콜에는 위조 방지 서명/인증된 페어링이 없다. 이를 바꾸려면 펌웨어와 앱을 함께 설계하고 보드 실물에서 검증해야 한다.
4. **수동 확인:** 실제 계정 로그인·토큰 만료·오프라인 로그아웃, 실제 보드 재연결, 잠금/해제 시 마지막 체크포인트, 실시간 전신·손 추적 정확도, Swift Playground 빌드는 별도 확인 대상이다. 이번 자동 테스트는 테스트용 Keychain 항목만 생성·삭제했고 실제 계정 탈퇴나 서버 데이터 쓰기를 실행하지 않았다.

이번 점검은 범위를 명시한 코드·회귀 검사이며, 전체 시스템에 취약점이 없다는 인증이나 외부 침투 테스트가 아니다.
