# MYMS 실행

## 주제신청서 기준 현재 범위

11월 19일 신청서의 공통 기능과 도전과제를 기준으로 개발합니다.
현재 내장 센서 구성은 Nano 33 BLE Sense Rev2이며, ToF 없이 IMU·제스처·밝기·상대 경사와 BLE 통신을 확인할 수 있습니다.
환경 기록은 사용자의 수정 요청에 따라 온습도·기압 대신 밝기·바닥 경사·운동기구·장소·신발로 구성합니다.
센서 탭에는 가속도 크기·최근 이력, 환경 측정·선택, 최근 제스처·근접 버튼 상태, LED 제어가 있습니다.
BLE 규격과 단위는 [BLE-PROTOCOL.md](docs/BLE-PROTOCOL.md)에 정리했습니다.

### 거리 센서 없이 확인하기

1. 앱 첫 화면에서 **로그인 없이 이 기기에서 시작**을 선택합니다. 서버 연결 없이 사용할 수 있습니다.
2. Arduino를 켜고 **센서** 탭에서 **기기 선택**으로 보드를 선택한 뒤, 읽어 온 아두이노 ID와 IMU 수신 상태를 확인합니다. 아래 환경 측정 절차를 진행하고 운동기구·장소·신발을 선택합니다.
3. 운동 계획을 추가하고 **이 운동 선택**를 누릅니다.
4. 센서 탭의 측정 방식을 **IMU 동작 테스트**로 바꾸고, **센서 없이 시연**은 끕니다.
5. 시작 후 보드를 손에 들고 움직여 횟수·세트·휴식을 시험합니다. 약 1.5g 이상에서 1회, 1.1g 이하로 복귀해야 다음 회가 가능하며 최소 간격은 0.5초입니다.
6. 종료 후 기록에서 환경값·메모를 확인합니다. 앱을 종료·재실행하고 같은 로컬 모드로 들어가 기록 유지를 확인합니다.

IMU 동작 테스트는 실제 사람의 운동 정확도 검증이 아니며 포인트·운동 통계에서 제외합니다.
고정된 보드는 사람의 운동을 IMU로 측정하지 못합니다. ToF 비접촉 카운트, 3종 운동 실측 수집·Core ML 분류 비교, 4방향 제스처 정확도 실험은 별도 검증이 필요합니다.
운동 중 연결이 끊기면 일시정지하며, 휴식 중 끊기면 자동 세트 전환을 멈추고 재연결 후 사용자가 다음 세트를 시작합니다.

### 환경 측정과 선택

- **밝기:** 센서를 가리지 않은 밝은 비교 환경에서 **현재 밝기를 기준으로 설정**을 누릅니다. APDS9960 clear 원시값(count)을 표시하며 lux가 아닙니다. 기준의 25% 이하를 ‘기준보다 어두움’으로 표시하는 초기 비교 기준입니다.
- **경사:** 수평이 확인된 면에 보드를 놓고 **수평 기준 보정**을 누른 뒤 2초 이상 움직이지 않습니다. 이후 운동할 바닥에 보드를 같은 면으로 놓고 다시 2초 이상 정지시킵니다. 기준면에 대한 상대 각도이며, 손에 든 보드의 각도는 바닥 경사가 아닙니다.
- **안정성:** 가속도 크기가 1g±8%이고 방향 변화가 2° 이내인 샘플을 2초 이상 받아야 경사를 표시합니다. 3° 이하의 ‘평평한 편’ 표시는 초기 비교 기준이며 운동 가능 여부의 판정이 아닙니다.
- **직접 선택:** 운동기구 있음/없음, 장소(집·체육관·야외·기타), 신발(맨발·양말·러닝화·기타)을 선택합니다. 미선택도 그대로 기록하며 센서가 자동 추측하지 않습니다.

운동 **시작 시점**의 환경값과 선택을 복사해 결과에 저장합니다. 이후 보드를 움직여 IMU 동작 테스트를 해도 시작 환경은 바뀌지 않습니다. 새 운동 전 환경을 다시 확인하세요.
끊기거나 오래된 센서값은 미측정으로 표시합니다. 재연결하면 밝기·수평 기준을 다시 설정합니다.
이전 온습도·기압 기록은 호환성을 위해 유지하고 History의 ‘이전 형식’에서만 보여줍니다. 새 기록에서는 수집하지 않습니다.

## 코드 구조

### 카메라 전신 자세 보조

운동 탭에서 **카메라 자세 보조**를 켜면 MoveNet SinglePose Thunder가 한 사람의 코·눈·귀·어깨·팔꿈치·손목·골반·무릎·발목 17개 지점을 추정합니다. 감지 신뢰도가 낮은 점은 숨기며, 보이지 않는 신체 부위를 임의로 그리지 않습니다. 화면을 보면서 운동할 수 있도록 전면 카메라만 사용하고, 지원 기기에서는 전면 초광각을 우선 선택합니다. 영상과 분석은 기기 안에서만 처리합니다. 카메라가 운동 횟수를 자동 집계하지는 않습니다.

같은 화면에서 MediaPipe Gesture Recognizer가 양손 각각 21개 지점을 청록색 점과 선으로 표시합니다. 영상 위의 부위 이름과 손모양 키워드는 표시하지 않습니다. 분류 신뢰도 0.6 이상인 펼침·주먹만 확정하며 다른 손모양이나 부분 손은 판별 중으로 둡니다. 손이 멀거나 작게 보이면 손가락 구분이 어려울 수 있으므로 손바닥이 충분히 보이게 배치합니다. 손동작으로 운동을 자동 조작하지는 않습니다.

가로 화면은 큰 카메라와 운동 진행/버튼을 나란히, 세로 화면은 카메라를 맨 위에 배치합니다. 운동 계획이 없거나 선택하지 않았으면 기본 푸시업을 표시하지 않고 계획 추가/선택을 안내합니다. 운동 탭의 선택 메뉴 또는 운동 안내의 **이 운동 선택**으로 준비합니다. 카메라를 켜는 것만으로 횟수 측정이 준비되지는 않으며, 선택한 방식의 유효한 아두이노 측정값이 있어야 실제 운동을 시작할 수 있습니다. 시작할 수 없으면 버튼 아래에 이유를 표시합니다. 센서 연결·측정 방식·시연 설정은 **센서** 탭에서 변경합니다.

Thunder 모델과 TensorFlowLite 런타임은 프로젝트에 포함되어 실행 중 다운로드하지 않습니다. 런타임 출처·패키징은 `MYMS.swiftpm/Vendor/TensorFlowLite`, 모델 출처·라이선스는 `MYMS.swiftpm/Sources/AppModule/PoseResources/NOTICE.md`에 기록했습니다. 실제 iPad의 기준 사진 추론 검사는 통과했으며, 사용자 실시간 동작 추적과 Swift Playground 빌드는 별도 검증 대상입니다.

Xcode와 Swift Playground는 `MYMS.swiftpm/Sources/AppModule` 아래의 같은 소스를 사용합니다.

```text
App/                      앱 시작점 (MYMSApp)
Models/                   운동·기록·난이도, 계정·연령대 모델
Services/                 Supabase 통신, 계정, 운동 저장, Bluetooth·운동 판정
Views/
  WorkoutHome.swift       탭 구성과 공유 화면 상태
  Authentication/         로그인·회원가입과 공통 입력 화면
  Plans/                  운동 계획·편집·안내·동작 애니메이션
  Workout/                실시간 운동·휴식·결과 화면
  History/                운동 기록·메모·삭제 화면
  Settings/               계정 설정·로그아웃·탈퇴 화면
  Shared/                 여러 화면에서 사용하는 연령대 선택기
```

탭별 화면은 `WorkoutHome`의 extension으로 나누어 기존 상태와 동작을 유지합니다.
Swift Playground는 소스 폴더 안의 Swift 파일을 함께 빌드합니다.
새 Swift 파일을 추가하면 Xcode 프로젝트의 소스 목록에도 등록해야 합니다.

## iPad Swift Playground (Mac 없이 실행)

앱의 최소 지원 버전은 iPadOS 17입니다. iPadOS에 맞는 최신 Swift Playground를 설치합니다.
`MYMS.swiftpm`은 iPad에서 여는 앱 프로젝트이며, Xcode 프로젝트도 이 안의 동일한 Swift 소스를 사용합니다.

1. Windows에서 저장소 루트의 `MYMS.swiftpm` 폴더 전체를 ZIP으로 압축합니다. `Package.swift`만 따로 전달하면 실행되지 않습니다.
2. ZIP을 iCloud Drive 또는 사용하는 파일 전송 서비스로 iPad에 전달하고 파일 앱에 저장합니다.
3. 파일 앱에서 ZIP을 풀고 `MYMS.swiftpm`을 Swift Playground로 엽니다. 연결 앱이 표시되지 않으면 Swift Playground의 문서 탐색기에서 해당 프로젝트를 선택합니다.
4. 실행 버튼을 누르고 Bluetooth 권한 요청을 허용합니다. 권한은 `AppInfo.plist`에 선언되어 있습니다. 필요하면 앱 설정의 Capabilities에서 Bluetooth 항목도 확인합니다.
5. **로그인 없이 이 기기에서 시작** 또는 인터넷 회원가입·로그인을 선택하고, 운동 계획을 추가합니다. 운동 안내에서 **이 운동 선택**를 선택합니다.
6. 센서 탭에서 **센서 없이 시연**을 켠 뒤 운동 탭으로 돌아와 시작합니다. 시작 거리 측정이 끝나면 **가상 동작 1회**로 횟수와 세트 전환을 확인합니다. 시연 결과는 이 기기의 기록에 저장하며 서버에 전송하지 않습니다.

센서를 사용할 때는 시연을 끄고 Arduino의 전원을 켠 뒤 연결과 거리 수신을 확인합니다.
로컬 모드에서는 서버 없이 시연·센서 테스트·기록을 사용할 수 있습니다.
Windows에서는 SwiftUI/CoreBluetooth 앱을 빌드할 수 없으므로 최종 컴파일과 센서 동작은 iPad에서 확인해야 합니다.
Swift Playground 안에서 실행하는 구성으로, 홈 화면에 독립 앱을 설치하거나 TestFlight로 배포하는 절차와는 다릅니다.

PowerShell에서 전송용 ZIP 만들기:

```powershell
New-Item -ItemType Directory -Force build | Out-Null
Compress-Archive -LiteralPath MYMS.swiftpm -DestinationPath build/MYMS-Playground.zip -Force
```

수정 후 ZIP을 다시 만들어 전달합니다. iPad에서는 기존 사본과 구분하여 최신 프로젝트를 엽니다.
Swift Playground에서 수정한 코드는 Windows 저장소에 자동 반영되지 않습니다.

참고: [Apple 앱 권한 안내](https://developer.apple.com/documentation/swift-playgrounds/project-capabilities)

## Arduino

Arduino IDE에서 Nano 33 BLE를 선택합니다. 현재 펌웨어는 실제 확인한 Sense Rev2 내장 센서용입니다. Rev1은 다른 센서 라이브러리 대응이 필요합니다.
Library Manager에서 ArduinoBLE, Arduino_APDS9960, Arduino_BMI270_BMM150, VL53L0X by Pololu를 설치합니다.
거리 센서를 추가할 때만 VL53L0X 모듈을 3.3V, GND, A4(SDA), A5(SCL)에 연결하고 센서가 측정 부위를 향하도록 배치합니다.
Arduino/MYMS/MYMS.ino를 열어 업로드합니다. 초기화 오류는 115200 baud 시리얼 모니터에서 확인합니다.

VL53L0X가 없어도 BLE 광고와 연결은 동작합니다. 거리값은 유효 측정 없음에 해당하는 `0`을 보내므로 ToF 방식의 운동 횟수는 측정하지 않습니다.
시리얼 모니터에는 1초마다 거리 센서·제스처 센서·BLE 연결 상태가 표시됩니다.
센서를 나중에 연결하면 보드를 재시작해 다시 초기화합니다. 센서 없이 운동 흐름을 확인할 때는 앱의 **센서 없이 시연**을 사용합니다.

## iPhone

MYMS.xcodeproj를 열고 MYMS 타깃의 Signing & Capabilities에서 Team을 설정합니다.
실제 iPhone을 실행 대상으로 선택하고 Run을 누릅니다. 앱의 Bluetooth 권한을 허용합니다.

센서가 연결되면 시작 버튼 또는 오른쪽 스와이프로 운동을 시작하고, 가슴을 센서 위에 둔 채 화면이 운동 중으로 바뀔 때까지 시작 자세를 유지합니다.
운동 계획 탭에서 푸시업, 스쿼트, 힙 브리지, 앉아서 무릎 들기 중 하나를 고르고 난이도, 목표 횟수, 세트 수, 휴식 시간을 설정합니다. 기본 푸시업 계획은 중급 깊이 50%, 10회씩 3세트, 휴식 30초입니다. 스쿼트, 힙 브리지, 앉아서 무릎 들기의 센서 배치와 판정 기준은 실측으로 확인해야 합니다. 힙 브리지와 앉아서 무릎 들기는 센서를 측정 부위 위에 단단히 고정해 아래를 향하게 합니다. 기존 계정에는 운동 계획의 추가 버튼으로 새 운동을 등록합니다.
왼쪽 스와이프는 일시정지, 오른쪽은 재개, 일시정지 중 아래 스와이프는 종료, 휴식 중 위 스와이프는 다음 세트를 시작합니다.

## 기록과 포인트

### 진행 중 저장과 복구

실제 센서를 사용하는 운동은 시작 시 세션 UUID를 만들고 횟수·세트·상태·시작 환경을 같은 기기의 계정별 로컬 파일에 저장합니다.
유효 횟수·상태가 바뀔 때 즉시, 진행 시간은 약 1초마다 저장합니다. 가상 시연은 진행 중 복구에서 제외하지만 종료 결과는 ‘센서 없이 시연’ 기록으로 이 기기에 저장합니다.
앱을 다시 실행해 같은 계정 또는 같은 로컬 모드로 들어가면 **복구** 또는 **진행 기록 버리기**를 선택합니다.
복구는 일시정지 상태이며 센서를 연결한 뒤 사용자가 **재개**해야 합니다. ToF는 시작 자세를 다시 측정하고 IMU는 낮은 가속도 구간을 먼저 받아야 다음 동작을 셉니다.
휴식 중 중단됐다면 남은 시간을 보존하고 **남은 휴식 재개** 또는 **다음 세트**를 직접 선택합니다. 앱 비활성화·연결 해제 시에도 자동으로 다음 세트를 시작하지 않습니다.

복구한 세션은 처음 만든 UUID를 유지합니다. 완료 기록·일일 포인트 한도·전송 대기열·완료 ID·진행 삭제를 하나의 원자적 파일 쓰기로 처리합니다.
기록을 삭제한 뒤 같은 완료 요청을 다시 받아도 완료 ID를 확인하므로 기록이나 포인트를 재생성하지 않습니다.
저장 실패 시 운동을 멈추고 오류를 표시합니다. 앱을 닫기 전에 저장 재시도를 해야 하며, 실패한 변경은 마지막으로 성공한 저장까지만 복구할 수 있습니다.
앱이 꺼져 있거나 센서가 끊긴 동안의 동작·전송되지 않은 부분 동작은 복원하지 않습니다. 중단·꺼짐 시간은 운동 경과 시간에 더하지 않습니다.

Arduino는 센서값만 보내며 Supabase의 세션·계정·포인트를 읽지 않습니다. 이번 작업은 Supabase 서버·테이블·설정·마이그레이션을 바꾸지 않습니다.
기존 서버 계정 전송은 같은 세션 UUID와 기존 `resolution=ignore-duplicates` 경로를 사용합니다. 서버의 여러 기기 간 중복·포인트 검증까지 보장하는 기능은 이번 범위가 아닙니다.

유효 횟수가 있는 세션은 완료하거나 종료할 때 계정별 로컬 파일에 저장됩니다. 기록 화면에서 결과·시작 환경값과 수동 선택을 조회하고 메모를 편집하거나 기록을 삭제할 수 있습니다.
서버 계정에서는 기존 운동 데이터 동기화도 유지합니다. 미전송 변경은 로컬에 보관해 재시도하며, 환경값·측정 방식은 현재 서버 스키마에 없어 해당 기기에만 보관합니다. IMU 테스트는 서버에 전송하지 않습니다.
기록 화면에는 이번 주 운동 횟수, 오늘 또는 어제로부터 이어진 연속 운동일, 한 세션 최다 횟수(PR)가 표시됩니다. IMU 테스트는 제외합니다.
초급·중급·상급는 유효 1회당 각각 1·2·3점, 목표를 채운 세트는 추가 5점입니다. 일일 한도는 300점이며, 기록을 삭제하면 그 기록의 포인트도 차감됩니다.

## 계정

이메일, 8자 이상의 비밀번호, 연령대를 입력해 가입합니다. 인증 메일이 발송되면 메일에서 주소를 확인한 뒤 로그인합니다.
로그인 상태는 기기의 Keychain에 저장되어 앱을 다시 열어도 유지되고, 로그아웃하거나 탈퇴하면 지워집니다. 서버에서 로그인이 만료되면 로그인 화면으로 돌아갑니다.
설정에서 로그아웃하거나 비밀번호를 다시 입력해 Supabase 계정과 운동 데이터를 삭제할 수 있습니다.
이전 로컬 계정과 운동 데이터는 서버 계정으로 자동 이전되지 않습니다.
로그인 없는 로컬 모드도 서버 계정과 별도이며, 기기·Playground 프로젝트 사본 간 자동 동기화는 하지 않습니다.

기존 계정은 설정에서 연령대를 입력할 수 있습니다. 운동 계획의 추천은 운동 종류, 연령대, 선택한 운동 경험을 반영하며, 적용 후에도 횟수와 세트를 편집할 수 있습니다.

## 센서 없이 시연

운동 계획에서 운동을 고른 뒤 센서 탭에서 **센서 없이 시연**을 켜고 운동 탭으로 돌아옵니다.
운동 시작 후 시작 거리 측정이 끝나면 **가상 동작 1회**를 눌러 횟수를 확인합니다.
목표에 도달하면 다음 세트 또는 결과 화면으로 이어집니다. 시연도 종료하면 기록 탭에 저장되며, 횟수가 0회여도 시연 결과를 남깁니다. 포인트·실제 운동 통계·서버 전송에서는 제외합니다. 결과의 **기록 보기**로 확인할 수 있습니다.

## Supabase

새 프로젝트를 구성할 때는 `supabase/migrations`의 SQL을 파일명 순서대로 적용합니다. 앱의 프로젝트 URL과 공개 API 키는 `MYMSCloud`에 설정합니다.

## 검증 범위

실제 Nano 33에서 새 펌웨어 컴파일·업로드 및 초기 읽기 후 구독 순서의 BLE 2회 연결을 확인했습니다. 밝기·3축 벡터 알림, 기존 LED 제어와 ToF 미연결 처리를 확인했습니다. 밝기·벡터 GATT 규격은 `docs/BLE-PROTOCOL.md`에 있습니다.
기본 ArduinoBLE에서는 전체 알림 중 추가 읽기·LED 쓰기 시간 초과가 재현됐습니다. HCI 로그에서 연결되지 않은 핸들의 완료 이벤트까지 전송 크레딧으로 계산하는 문제가 확인돼 프로젝트 빌드 사본에서 보정했습니다. 최종 보정 빌드에서 동시 읽기·LED·알림 시나리오 3회 연속 통과를 확인했습니다. 적용 방법과 후속 검증 결과는 Arduino/BLE-BUILD.md를 참고하세요. 수평 기준 보정과 실제 공간별 밝기·경사 정확도는 별도 실측이 필요합니다.
iOS는 보드 고유 ID를 읽고, 광고 ID가 있으면 대조한 뒤 LED 초기 상태와 필수 알림 구독을 확인합니다. 이전 기기의 늦은 콜백·탐색 오류·구독 실패·초기화 시간 초과를 처리합니다. 측정값이 끊기면 휴식 중에도 시간 진행을 멈추며, 유효한 선택 모드 데이터가 있어야 정상 수신으로 표시합니다.
Windows에서는 SwiftUI/CoreBluetooth 빌드와 iPad 화면·로컬 기록 재실행 검증을 실행하지 못했습니다.
`Tests`의 Swift 자체 검사 실행 방법은 [Tests/README.md](Tests/README.md)에 있습니다.

### BLE 시간 초과 보정 빌드

Nano33의 동시 알림·읽기 통신에는 프로젝트의 ArduinoBLE 보정이 필요합니다. 저장소 루트 PowerShell에서 `.\Arduino\build-and-upload.ps1 -Upload -Port COM5`로 빌드·업로드합니다. Arduino IDE 기본 업로드에는 보정이 포함되지 않습니다. 원인·적용 범위·재현 검사는 [Arduino/BLE-BUILD.md](Arduino/BLE-BUILD.md)를 참고하세요.
제공된 DB 컬럼과 현재 센서/앱 전송 범위는 [docs/DB-CONTRACT.md](docs/DB-CONTRACT.md)에 정리했습니다. DB 서버·스키마는 변경하지 않았습니다.

기록 화면 그래프 위의 **실제 운동 / 시연**으로 그래프와 최근 기록 목록을 함께 전환합니다. 시연 그래프는 시연 기록만 집계하며 포인트나 실제 운동 통계에 합산하지 않습니다. 0회로 종료한 시연은 기록 목록에 남지만 그래프 횟수는 0회입니다.
